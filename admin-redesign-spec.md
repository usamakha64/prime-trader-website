## 3. The Big Change — Bot Signals Replace Manual Signals

### Current (manual — REMOVE)
- "➕ Publish Signal" form (asset, CALL/PUT, confidence %) → admin types and publishes
- "Recent Signals — Mark Results" → admin clicks WIN/LOSS per signal

### New (bot — BUILD)
The Prime Trader app/bot becomes the signal engine. LegendJournal's pipeline was:
`extension → server → ADMIN PUBLISH → Telegram + website → manual trade → ADMIN MARK RESULT`

Ours becomes:
`bot (7-indicator strategy) → auto-publish → Telegram + website + app → user trades manually OR bot auto-trades → BOT AUTO-SETTLES win/loss`

**Admin Signals tab redesign:**

1. **🤖 Bot Status card** (NEW)
   - Bot connection: ● Connected / ● Disconnected (live)
   - SSID status: valid / expired (with "notify user" action)
   - Strategy: 7-indicator (EMA 9/21/50, RSI 14, ADX 14, ATR 14, BB 20,2)
   - Auto-publish: ON/OFF toggle
   - Auto-settle: ON/OFF toggle (if OFF → falls back to manual WIN/LOSS marking like LegendJournal)

2. **📡 Live Bot Signals table** (REPLACES manual publish form)
   - Columns: Time | Asset | Direction | Confidence | Expiry | Status (OPEN/WIN/LOSS/PENDING) | P&L
   - Signals appear automatically as bot generates them
   - Results auto-marked by bot at expiry (0-sec local result + API confirm)
   - Admin can **override** any result (WIN↔LOSS) — override logged in Audit Log
   - Filter: today / this week / all; filter by result

3. **📊 Session Summary card** (NEW — matches LegendJournal's Telegram summary)
   - Signals today, wins, losses, win rate, total P&L
   - "📢 Broadcast summary to Telegram" button

4. **Manual publish** (KEEP as fallback, collapsed)
   - Keep the manual form but move it into a collapsed "Manual signal (fallback)" section
   - For when bot is offline

### Database changes needed (Supabase)

```sql
-- signals table: add bot columns
alter table signals add column if not exists source text default 'manual';   -- 'bot' | 'manual'
alter table signals add column if not exists status text default 'open';     -- 'open' | 'win' | 'loss' | 'pending'
alter table signals add column if not exists entry_price numeric;
alter table signals add column if not exists exit_price numeric;
alter table signals add column if not exists expiry_seconds int;
alter table signals add column if not exists settled_by text;                -- 'bot' | 'admin'
alter table signals add column if not exists mtg_level int default 0;
alter table signals add column if not exists strategy text;                  -- '7-indicator'
```

### Bot → Website API flow
1. Bot generates signal → POST to website API → row in `signals` (source='bot', status='open')
2. Website pushes to: customer dashboard (login-only), Telegram channel
3. At expiry: bot settles → PATCH `signals` (status win/loss, exit_price) → settled_by='bot'
4. Admin sees it live in the table; can override if needed
